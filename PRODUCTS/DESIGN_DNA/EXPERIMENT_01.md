# Design DNA — Experiment 01: Website Revenue-Leak Watchdog

## 1. Product/customer
Primary audience: small SaaS, D2C and service-business operators who already have traffic but suspect their website is wasting some of it.

Customer anxiety:
"We are paying for traffic, but I don't know exactly where the page is losing people."

Desired first-visit feeling:
"Finally, someone is showing me the leak—not another generic audit score."

## 2. Product personality
Commercial, investigative, calm, precise, slightly forensic.

Never "AI magic". It should feel like a sharp revenue analyst inspecting a business instrument.

## 3. Visual metaphor
**Revenue Control Room / Leak Investigation**

The main visual is a diagnostic board:
traffic enters -> conversion path -> friction points -> value at risk -> prioritized fixes.

Do not use robots, brains, glowing orbs, floating AI blobs or decorative 3D.

## 4. Color system
Foundation:
- warm ivory #F4F0E7
- charcoal #171817
- paper #FFFDF8

Signals:
- signal orange for active leak / action
- restrained blue for neutral evidence
- muted green only for verified healthy states
- muted red only for severe warnings

No neon purple.

## 5. Typography
Editorial sans + compact data typography.

Hierarchy:
- large, high-contrast diagnostic headline
- compact uppercase labels
- readable body copy
- tabular/monospace treatment for scores, URLs and evidence values where useful

## 6. Layout grammar
- asymmetrical editorial grid
- generous margins
- horizontal evidence rails
- diagnostic cards instead of generic bento cards
- visible progression from URL -> evidence -> leak -> fix
- no decorative section count inflation

## 7. Hero composition
Left:
"Your website may be leaking conversions."

Immediately explain:
Paste a public URL. Get the 3 highest-priority conversion leaks and what to fix first.

Right:
A truthful simulated diagnostic instrument showing:
- URL
- conversion path
- 3 leak markers
- impact/effort ranking

Label simulation/example clearly.

Primary CTA:
"Run the $1 Diagnostic"

Secondary:
"See a sample report"

## 8. Product visualization
Use a real report-like interface:
- page snapshot region
- annotated evidence markers
- leak severity
- impact/effort matrix
- fix recommendation

The visual must explain the workflow without pretending to have audited the visitor's site before submission.

## 9. Motion language
Purposeful:
- URL input transforms into a diagnostic scan state
- evidence markers appear sequentially
- priority ranking settles into place
- CTA remains stable

Keep motion short and restrained.
Reduced motion: static transitions and no moving scan effects.

## 10. Trust/proof
Allowed:
- methodology
- sample report
- transparent assumptions
- evidence labels
- pricing
- "no login required for public-page diagnostic"

Not allowed:
- fake testimonials
- fake customer logos
- fake revenue increases
- fake audit counts
- invented accuracy percentages

## 11. CTA hierarchy
1. Run the $1 Diagnostic
2. See Sample Report
3. Premium CTA only after the paid output is understood

## 12. Mobile behavior
Mobile is not a compressed desktop:
- URL field and CTA stack
- diagnostic board becomes vertical
- evidence remains readable without horizontal scrolling
- priority finding stays above secondary details
- payment CTA remains visible after preview

## 13. Performance budget
- no heavy 3D dependency
- no video hero
- minimal JavaScript before interaction
- system/web-safe fonts where possible
- avoid blur/backdrop-filter as a structural dependency

## 14. Accessibility
- semantic headings
- keyboard-accessible URL input and CTA
- visible focus states
- sufficient contrast
- reduced-motion support
- errors stated in text, not only color

## 15. Design rejection test
Reject the implementation if it could plausibly be mistaken for:
- a generic AI SaaS landing page
- a ChatGPT wrapper
- a template with swapped copy
- a neon-purple AI dashboard

The strongest visual should be the revenue-leak diagnostic itself.
