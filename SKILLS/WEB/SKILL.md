# Web Skill

## Purpose
Research and execute legitimate web workflows.

## Research
Use current sources when freshness matters. Record source, date/context and confidence.

## Browser actions
Before submitting or changing anything externally, verify target, fields and scope. Respect site rules and rate limits.

## Extraction
Do not invent missing fields. Mark unavailable data explicitly.

## External action
Draft first when practical. Human approval is required for mass outreach, purchases, legal submissions and other high-impact actions.


## Design-first website workflow
1. Research the customer, category and strongest current references.
2. Produce a Design DNA before coding.
3. Define a product-specific visual metaphor and information hierarchy.
4. Prefer truthful product UI/workflow visuals over generic illustrations.
5. Use 3D only when it helps explain the product or creates meaningful interaction.
6. Define motion purpose, duration and reduced-motion behavior.
7. Implement mobile-first responsive behavior.
8. Run the Web Design Quality Gate.
9. Inspect the deployed/rendered result, not only source code.
10. Record important design decisions and evidence.

## Anti-generic rules
- Never reuse a prior project's palette, hero composition or visual language merely because it is convenient.
- Purple is an option, not a default.
- Avoid generic AI brains, glowing orbs, gradient blobs, glass cards and excessive bento layouts unless research shows they fit the product.
- Do not call a site premium merely because it has gradients, blur, shadows or animations.
- The product's actual value should be the strongest visual element.
